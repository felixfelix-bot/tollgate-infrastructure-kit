## 3. Root Cause Analysis: Why VPS2 Is Missing Routes

### Problem 1: Standalone strfry container missing
The `strfry` role in `setup-vps-2.yml` (line 13) should deploy `tollgate-strfry` on port 7777. The role tasks are straightforward (create dir, copy compose, start container). If the container is absent:
- The playbook may have been run selectively (not all roles)
- Docker may have failed to pull `ghcr.io/hoytech/strfry:latest`
- The container may have been manually removed
- Port conflict with strfry-agg (different port 7779, so unlikely)

### Problem 2: Caddy not running as Docker container
The `caddy` role deploys Caddy as Docker container `tollgate-caddy` with `network_mode: host`. VPS2 has a **systemd Caddy** instead. This means:
- The Ansible-generated `Caddyfile.http.j2` template (which produces the full route set) is deployed to `/opt/tollgate/caddy/Caddyfile` for the Docker container
- The systemd Caddy has its own Caddyfile (likely at `/etc/caddy/Caddyfile`) with only the manually-added plebeian market routes
- **The two Caddy instances conflict** — only one can bind ports 80/443
- VPS2's systemd Caddy is winning, so the Ansible-managed Docker Caddy routes are never served

### Problem 3: machine_active: false gating
The `machine_active: false` in `m2.yml` intentionally skips:
- `git.{base_domain}` (grasp)
- `routstr.{base_domain}`
- `runner.{base_domain}`
- `*.mints.{base_domain}` (mint wildcard)

This is **by design** for active/standby. However, if the goal is to have VPS2 serve core nostr infrastructure, the core routes (relay2, blossom2, ngit2, nsite, chat, agg) are NOT gated by `machine_active` — they should render. The issue is that the Docker Caddy isn't running, so even if the Caddyfile is correct, no one is serving it.

## 4. What Ansible Playbook Changes Are Needed

### Change 1: Deploy standalone strfry on VPS2 (already in playbook, needs execution)
The `strfry` role is already in `setup-vps-2.yml` line 13. No playbook change needed — **just run the playbook**:
```bash
ansible-playbook ansible/playbooks/05-strfry.yml -l vps2
```
Or the full setup:
```bash
ansible-playbook ansible/playbooks/setup-vps-2.yml -l vps2
```

### Change 2: Switch VPS2 from systemd Caddy to Docker Caddy
The `caddy` role deploys Docker Caddy. If VPS2 currently has systemd Caddy:
1. Stop and disable systemd Caddy: `systemctl stop caddy && systemctl disable caddy`
2. Run the caddy role to deploy Docker Caddy: `ansible-playbook ansible/playbooks/04-caddy.yml -l vps2`
3. The Docker Caddy will pick up the full `Caddyfile.http.j2` template with all routes

**Alternatively**, if systemd Caddy is preferred on VPS2, the Caddyfile template needs to be copied to `/etc/caddy/Caddyfile` instead of `/opt/tollgate/caddy/Caddyfile`. This would require modifying the caddy role to support both deployment modes.

### Change 3: If keeping machine_active: false, no changes needed for core routes
The core nostr routes (relay2, blossom2, ngit2, nsite, chat, agg) are NOT gated by `machine_active`. They will render correctly once the Docker Caddy is running with the Ansible-generated Caddyfile.

### Change 4 (optional): Set machine_active: true on VPS2
If VPS2 should also serve grasp/git, routstr, act_runner, and mint wildcard:
- Edit `ansible/inventory/group_vars/m2.yml` line 6: `machine_active: true`
- This will enable the gated routes in the Caddyfile template
- **Warning:** This would create duplicate routes for shared subdomains (git, routstr, runner) pointing to both VPS IPs — Cloudflare round-robin would alternate between VPS1 and VPS2. Only do this if VPS2 actually runs these services.

### Change 5: Fix ngit_relay_domain mismatch
The `ngit_relay` role defaults `ngit_relay_domain: "ngit.{{ base_domain }}"` but the Caddyfile template generates `ngit{{ machine_number }}.{{ base_domain }}` (i.e., `ngit2.{{ base_domain }}` on VPS2). The health check in the ngit_relay role (line 40-44) verifies `https://{{ ngit_relay_domain }}` which would check `ngit.{base_domain}` not `ngit2.{base_domain}`. This verification will fail on VPS2. Fix: set `ngit_relay_domain` per-machine in `m2.yml`:
```yaml
ngit_relay_domain: "ngit2.{{ base_domain }}"
```
